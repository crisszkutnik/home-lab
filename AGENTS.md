# AGENTS.md

## What this repo is

GitOps repository for a personal, on-premise Kubernetes home cluster. The desired state of the cluster lives here and is reconciled continuously by Flux. The repo also contains the Ansible playbooks used to provision nodes and the Terraform configuration for Cloudflare.

Public docs: <https://blog.cristobalszk.dev/docs/home-cluster/infrastructure/>

## Tech stack

| Area | Tooling |
| --- | --- |
| Cluster | K3s (1 control plane + 2 workers), Ubuntu on OrangePi 5 (RK3588S, 4 GB RAM, 64 GB disk) |
| GitOps | Flux v2 (`GitRepository` + `Kustomization`), Kustomize |
| Packaging | Helm via Flux `HelmRelease`; charts from `HelmRepository` resources |
| Ingress | ingress-nginx, host `private-k8s.cristobalszk.dev` |
| Load balancer | MetalLB in L2 mode, pool `192.168.0.190-192.168.0.199` |
| Secrets | External Secrets Operator + 1Password Connect (vault `K3s_cluster`) |
| Observability | kube-prometheus-stack (Prometheus, Alertmanager), Grafana, Loki, Promtail |
| Messaging | Strimzi / Kafka (KRaft, single broker) |
| Provisioning | Ansible (K3s install, netplan, cloudflared) |
| Edge / public access | Cloudflare Tunnels + Cloudflare Access + WARP, managed with Terraform |
| Automation | Renovate (dependency updates), TruffleHog secret scan via GitHub Actions |

The nodes are small (4 GB RAM). Keep resource requests/limits modest and avoid heavy defaults; existing manifests deliberately disable caches/replicas for this reason.

## How reconciliation works

`clusters/base` is the root. Its Kustomizations run in this order:

1. `repositories` – creates all `HelmRepository` objects from `clusters/repositories`.
2. `core` – namespaces and platform components.
3. `core-config` – configuration depending on `core` CRDs (MetalLB pool, ESO store).
4. `apps` – all workloads; depends on `repositories`, `core`, and `core-config`.

Each directory has a `kustomization.yaml` listing its resources. When adding a new app or component, add a folder plus an entry in the parent `kustomization.yaml`.

`clusters/base/flux-system/gotk-*.yaml` is generated by `flux bootstrap`. Do not hand-edit it.

## Conventions

- **Images** are pinned to explicit tags in Deployments. Renovate updates them; do not use `latest`.
- **Helm charts** are pinned via `spec.chart.spec.version` in `HelmRelease`, with `interval: 10m` and a `sourceRef` to a `HelmRepository` in `flux-system`.
- **Namespaces**: personal apps go in `default`; platform pieces in `networking`, `monitoring`, `security`, `kafka`. Namespaces are declared in `clusters/core/namespaces/`.
- **Ingress**: use `ingressClassName: nginx`, host `private-k8s.cristobalszk.dev`, and path-based routing. Public endpoints use `public-k8s.cristobalszk.dev` (avoid unless intended).
- **Auth on ingresses**: add label `auth.cristobalszk.dev/enabled: "true"`. `clusters/apps/default/auth-transformer.yaml` injects the nginx `auth-url` annotations pointing at `auth-service`.
- **Secrets**: never commit plaintext. Create an `ExternalSecret` referencing `ClusterSecretStore/1password-secrets-store` and consume the generated Secret via `secretKeyRef`. The 1Password item key is set in `spec.dataFrom[].extract.key`.
- **Disabled apps**: some entries in `clusters/apps/default/kustomization.yaml` are intentionally commented out (`expenses-receiver`, `server`, `client`). Do not re-enable without reason.
- Keep YAML consistent with the surrounding files (2-space indent, `---` separators only where already used).

Personal services pulled from `ghcr.io/crisszkutnik/*`: `auth-service`, `expenses-api` (`expenses-save-api`), `expenses-ui`, `expenses-receiver`, `server`, `client` (`dashboard`), `discord-notifier`, `telegram-bot`, `finance-market-data-puller`, `dollar-data-to-google-sheets-etl`, plus `hello-node` (smoke test).

## Secrets flow

1. 1Password Connect runs in the `security` namespace (`clusters/core/security/1password-connect`).
2. ESO runs in `security`; its `ClusterSecretStore` (`clusters/core-config/security/external-secrets-operator/1password-secrets-store.yaml`) points at Connect and vault `K3s_cluster`.
3. Apps declare `ExternalSecret` resources (usually named `secret.yaml`) that materialize Kubernetes Secrets.

Force a re-fetch: `kubectl annotate es <name> force-sync=$(date +%s) --overwrite`, then restart pods that use the secret.

## Ansible

Run from the `ansible/` directory:

```bash
ansible-playbook ./playbooks/<playbook>.yaml
```

- `ansible.cfg` sets `roles_path=./roles` and inventory `./inventory/hosts.yaml`.
- `inventory/hosts.yaml` defines `setup_node` and `prereq` groups; most active hosts are commented out.
- Playbooks: `preconfigure_node` (apt upgrade + netplan/hostname/static IP), `setup_node` (K3s server/agent, kubectl, Flux CLI, GHCR registry config, cloudflared), `setup_cloudflared` (tunnel client), `upgrade` (apt update/upgrade).
- Secrets/tokens come from environment variables via `lookup('ansible.builtin.env', ...)` (`NODE_TOKEN`, `AGENT_TOKEN`, `TUNNEL_TOKEN`, GHCR credentials, etc.). Never hardcode them.

New-node flow: run the manual apt/NetworkManager commands in `ansible/README.md`, configure the inventory entry, then run `preconfigure_node` and `setup_node`. Also add the node's logical IP as a Terraform target.

## Terraform (Cloudflare)

Config lives in `terraform/cloudflare/` (Terraform 1.10.5, provider `cloudflare ~> 4.0`).

- Manages the tunnel, tunnel config/route, virtual network, Access applications/policies, WARP device profile/split tunnel, and infrastructure access targets.
- Tunnel ingress routes both `public-k8s.cristobalszk.dev` and `private-k8s.cristobalszk.dev` to `http://localhost:32415` (ingress-nginx NodePort) on each node.
- State is stored locally and **not** in the repo; `terraform.tfvars` and state are kept in 1Password.
- Setup: export `CLOUDFLARE_API_TOKEN`, restore `terraform.tfvars` and state from 1Password, then `terraform init`.
- Requires variables: `account_id`, `home_cluster_tunnel_secret`, `allowed_emails`, `ssh_usernames`, `tunnel_ipv4_ips`.

Do not commit `terraform.tfstate*`, `terraform.tfvars`, or `.env` (already gitignored under `terraform/cloudflare/`).

## Networking / infrastructure

- LAN: `192.168.0.0/24`; gateway `192.168.0.1`.
- DHCP: `192.168.0.10-189`; MetalLB: `.190-199`; masters: `.200-210`; nodes: `.211-254`.
- Node hostnames/IPs: `cluster-master-0` = `192.168.0.200` (control plane), `cluster-master-1` = `192.168.0.211` (worker), `cluster-master-2` = `192.168.0.212` (worker).
- Logical (Cloudflare tunnel VNET `170.0.0.0/24`) IPs: `170.0.0.1`, `170.0.0.2`, `170.0.0.3` respectively.
- Each node runs `cloudflared`; traffic enters Cloudflare, reaches nginx on port `32415`, then routes by ingress rules.
- `private-k8s` is protected by Cloudflare Access (email allowlist + service token). SSH access is via Cloudflare infrastructure access targets.

## CI and automation

- `.github/workflows/scan-credentials.yml`: TruffleHog on pushes/PRs to `main` and manual dispatch.
- `renovate.json`: Flux and Kubernetes managers scan `clusters/**/*.yaml`; `clusters/base`, `clusters/repositories`, release files, and kustomization files are ignored. Patch updates auto-merge; timezone `America/Argentina/Buenos_Aires`.

## Useful commands

```bash
# Validate rendered manifests locally
kubectl kustomize clusters/apps
kubectl kustomize clusters/core

# Flux status / forced reconciliation
flux get kustomizations
flux reconcile kustomization apps --with-source

# Debug a failing HelmRelease
kubectl describe helmrelease <name> -n <namespace>
flux logs --kind HelmRelease --name <name> --namespace <namespace>
flux reconcile helmrelease <name> --force --with-source --reset --namespace <namespace>
```

## Notes for agents

- Prefer minimal, targeted changes; this repo is the live cluster state, so a merged change is deployed.
- Do not add plaintext secrets, real tokens, or private IPs beyond the documented plan.
- Do not modify generated Flux bootstrap files (`gotk-components.yaml`, `gotk-sync.yaml`) or Flux state.
- When adding an app, include `kustomization.yaml`, pin image/chart versions, set resource limits, and wire the parent kustomization.
- No local test suite; validate with `kubectl kustomize`, `kubeconform`/`yamllint` if available, and `terraform validate` for Terraform changes.
